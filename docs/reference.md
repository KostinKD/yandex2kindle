# Yandex2Kindle — локальная библиотека

**Что работает:** локальная веб-панель, встроенный браузерный EPUB-ридер (Foliate-js), доставка книг на Kindle по email (Send-to-Kindle), извлечение настоящих обложек, серий и аннотаций, хаб цитат и заметок с Markdown-экспортом, статистика и стрики чтения, загрузка EPUB/FB2/PDF/MOBI/AZW3/TXT/MP3/M4B (до 500 МБ), добавление в библиотеку Calibre через `calibredb`, автоматический импорт из папки `incoming` (Folder Watcher), предотвращение дубликатов по SHA-256, список чтения, OPDS 1.2 и собственный плагин для KOReader.

Также доступны поиск по названию и автору (включая кириллицу без учёта регистра), страницы библиотеки по 50 книг, поиск и пагинация OPDS, редактирование и удаление записей списка чтения, сохранение процента чтения в панели и позиции через API. Незавершённые веб-загрузки не попадают в сканирование `incoming`. Пустые файлы отклоняются; ограничение 500 МБ действует и при импорте папки.

**Интеграции:** импорт личной библиотеки Яндекс Книг в список чтения вручную или по расписанию, поиск Flibusta/другого OPDS-каталога, скачивание выбранного издания с импортом в Calibre и сервер синхронизации прогресса KOReader. Веб-страница интеграций — `/integrations`. Нужны собственный OAuth-токен и адреса каталогов. Подписочные файлы Яндекса не извлекаются, DRM не обходится.

## Компактный интерфейс библиотеки

- `/` — каталог: поиск по названию, автору, серии, жанрам и аннотации; фильтры формата, прогресса, автора, серии и полки; сортировка; сетка или список. Параметры сохраняются в URL и при пагинации.
- `/dashboard` — продолжить чтение, недавно добавленные книги и короткие счётчики.
- `/books/{id}` — чтение/аудиоплеер, файл/EPUB, ручные метаданные, оценка, отзыв, прогресс, полки и последние 30 цитат. Изменения метаданных хранятся в приложении; оригиналы и Calibre-библиотека не перезаписываются. Автоматические связи wishlist пересчитываются при изменении названия/автора; ручные сохраняются.
- `/wishlist` — отдельный список чтения с фильтрами и 50 записями на странице. Старая ссылка `/?wish_status=...` перенаправляется сюда.
- `/devices` — адреса OPDS/синхронизации и подключение устройства. Плагин KOReader 1.1 открывает OPDS, отправляет цитаты из открытой книги и загружает список цитат с сайта. Прогресс синхронизируется встроенным модулем KOReader.
- Полку можно создать даже в пустой библиотеке, а добавить/убрать книгу — на странице книги. Удаление доступно в каталоге в блоке «Управление полками» с повторным подтверждением; удаляется только полка, книги и прогресс сохраняются. Для сетки и списка используются те же серверные фильтры.

Навигация находится слева на компьютере и раскрывается кнопкой «Меню» на телефоне. Поддерживаются светлая, тёмная и системная темы. Service worker кэширует только статические ресурсы; личные HTML-страницы и файлы не доступны offline через общий кэш браузера.

`PATCH /api/books/{id}` принимает частичное обновление `title`, `author`, `series`, `series_index`, `description`, `genres`, `year`, `isbn`. `year: null` очищает год; пустое название и неизвестные поля отклоняются. `GET /api/books` поддерживает `q`, `shelf`, `format`, `status` (`all/reading/finished/unread`), `sort` (`newest/title/author/series/progress`), `author`, `series`, `limit`, `offset`.

## Установка

**Для обычного пользователя:** [НАЧНИТЕ ЗДЕСЬ.html](../НАЧНИТЕ%20ЗДЕСЬ.html) или [пошаговая инструкция](../НАЧНИТЕ%20ЗДЕСЬ.md).

1. Установите и откройте [Docker Desktop](https://www.docker.com/products/docker-desktop/). Завершите его первоначальную настройку; Windows может попросить перезагрузку.
2. Распакуйте архив приложения в постоянную папку. На macOS дважды нажмите `Запустить.command`, на Windows — `Запустить.bat`. Linux с Docker/Compose/curl: `sh scripts/launch.sh`.
3. Запускатор соберёт контейнер, дождётся готовности и откроет браузер. При занятом порте он попробует следующий и запомнит адрес в `data/launcher.port`. Ошибки сборки доступны в `data/launcher.log`.
4. В браузере создайте владельца. Логин/пароль и права первого владельца не нужно создавать через терминал. Одноразовый ключ передаётся запускатором в fragment URL, не отправляется в query и удаляется после регистрации. Повторная регистрация владельца запрещена.
5. Можно сразу загрузить книгу. Яндекс, SMTP, Telegram и каталоги настраиваются в **Настройках** на сайте, по отдельности и в любое время. Заполненные ключи не показываются повторно. Пустое секретное поле сохраняет прежнее значение; отключение — отдельной кнопкой.

Поддержаны выбор почтового сервиса с подстановкой SMTP для Яндекса/Mail.ru, ссылки на инструкции почты, пошаговый вход в Яндекс и проверки подключений без отправки писем/сообщений. Сохранённая конфигурация применяется без пересборки. Telegram подхватывает изменения в следующем цикле опроса (до 30 секунд), расписание Яндекса просыпается при изменении его настроек.

Конфигурация хранится в `data/configuration.sqlite` с правами 0600; это локальное хранилище, не зашифрованный сейф. Секреты не возвращаются в HTML или API настроек. Веб-настройки имеют приоритет над одноимёнными переменными окружения; существующие `.env` продолжают работать как резервные значения. Настройки сервера видит только владелец. Они не становятся общими ключами для личных интеграций других пользователей.

**Ручной запуск для разработчика:** `docker compose up -d --build`. Затем `docker compose exec yandex2kindle python -m app.setup` выводит локальную ссылку первого запуска (не публикуйте её). Прежний CLI `python -m app.auth` сохранён. `./scripts/start.sh` по-прежнему определяет IP для подключения устройства; в запускаторах это происходит автоматически. Адреса доступны на странице `/devices`, IP можно поправить в `/settings#device`. По умолчанию сайт работает на `http://localhost:8000`, порт меняется через `APP_PORT`.

**Архив для передачи другим:** `python3 scripts/package_release.py`. Полученный `dist/Yandex2Kindle.zip` содержит только приложение, запускаторы и инструкцию; `.env`, `data`, `incoming`, `.git` и кэши туда не включаются. Скрипт сохраняет права запуска `.command`/`.sh` в ZIP. Это исходная сборка через Docker, не подписанный установщик ОС. Docker и разрешения системы остаются обязательным внешним шагом. Фактический запуск PowerShell на Windows требует проверки на Windows.

Calibre-библиотека — `./data/calibre`, оригиналы — `./data/originals`, состояние — `./data/app.db`. Calibre Content Server не включён: OPDS реализован приложением. Для настольной Calibre не открывайте одну библиотеку на запись одновременно с импортом приложения.

### Личные библиотеки и OPDS

Для встроенного браузера Kindle откройте `http://IP_КОМПЬЮТЕРА:8000/kindle`. Это отдельная облегчённая версия без изображений, внешних шрифтов и CSS-файлов: чёрный текст на белом фоне, обычные формы, поиск, 15 книг на страницу, скачивание оригинала и экспорт EPUB. Доступны список чтения (`/kindle/wishlist`), поиск по Flibusta и OPDS с перелистыванием страниц, выбор издания, импорт и скачивание, а также синхронизация списка Яндекс Книг (`/kindle/integrations`, только для владельца). При импорте из списка чтения книга связывается с выбранной записью. Рядом с редактируемыми полями в обеих версиях есть кнопка «Очистить»: она использует небольшой локальный скрипт, совместимый со старыми браузерами. Остальные функции, вход и выход работают без JavaScript; после входа пользователь остаётся в лёгкой версии. Кнопка «Версия для Kindle» есть в шапке обычной страницы; ссылка также доступна внизу. Возможность скачать и открыть конкретный формат зависит от модели и прошивки Kindle; EPUB-ссылка не выполняет Send to Kindle и не конвертирует файл в формат штатной читалки Kindle. Для чтения через KOReader можно продолжать использовать OPDS.

Если пароль владельца забыт, выполните `docker compose exec yandex2kindle python -m app.auth --reset-owner`. Команда запросит новый пароль скрыто, сообщит логин владельца и завершит его веб-сессии. Книги, прогресс и существующий пароль синхронизации KOReader сохраняются. Восстановление доступно только через консоль сервера.

На странице «Аккаунт» владелец создаёт пользователей. Открытой регистрации нет. Каждый пользователь получает отдельные SQLite-базу, Calibre-библиотеку, оригиналы, кэш конвертации, список чтения и прогресс в `data/users/<id>/`. Учётные записи и сессии хранятся в `data/accounts.sqlite`; пароли защищены солёным scrypt-хешем, токены сессий хранятся в виде SHA-256. Сделайте резервную копию всей папки `data` перед обновлением.

Личный OPDS поддерживает HTTP Basic: логин и пароль те же, что на сайте. Поиск, переходы по страницам, оригиналы и экспорт EPUB требуют авторизации. Для файлов другого пользователя сервер возвращает 404; одинаковые номера книг в разных библиотеках относятся к разным файлам. Для не-EPUB книг каталог дополнительно предлагает EPUB с локальной конвертацией Calibre. Клиент должен передавать авторизацию также при скачивании файлов. Публичного общего каталога нет.

Интеграции, настроенные через `.env` (Яндекс, Flibusta, внешний OPDS), доступны только владельцу. Фоновая синхронизация относится только к его библиотеке. Индивидуальные токены Яндекса пока не поддерживаются. Общая папка `incoming` принадлежит владельцу; остальные пользователи загружают файлы через веб-форму.

Веб-формы используют сессионную cookie (HttpOnly, SameSite=Strict, срок 7 дней; Secure при HTTPS), проверку источника браузерных запросов и ограничение попыток входа. Для изменяющих API-запросов сначала выполните `POST /login` и используйте выданную cookie; HTTP Basic предназначен для чтения каталога и файлов. Старые примеры POST/PATCH/PUT/DELETE ниже требуют этой cookie. Сессия завершается кнопкой «Выйти» на странице аккаунта.

## Импорт папки

Скопируйте файлы в `incoming/`, затем:

```bash
curl -b cookies.txt -X POST http://localhost:8000/scan
```

Успешно импортированные файлы удаляются из `incoming/`, ошибки остаются на месте. Сервис не рекурсивно сканирует подпапки.

## API

- `GET /` — веб-интерфейс
- `POST /upload` — добавление файла в Calibre
- `POST /wishlist` — добавление книги в список чтения
- `GET /api/books?q=Толстой&limit=50&offset=0` — поиск и страницы импортированных книг (`limit`: 1–200; по умолчанию 50)
- `GET /api/wishlist` — список чтения
- `PATCH /api/wishlist/{id}` — изменить название и автора: JSON `{"title":"Название","author":"Автор"}`
- `DELETE /api/wishlist/{id}` — удалить запись списка чтения
- `GET /api/books/{id}/progress` — получить прогресс книги
- `PUT /api/books/{id}/progress` — сохранить прогресс: JSON `{"progress":0.45,"position":"chapter:3"}` (доля от 0 до 1; позиция — строка клиента)
- `GET /opds?q=Толстой&limit=50&offset=0` — OPDS-каталог с поиском и ссылками на страницы
- `GET /opds/search.xml` — описание OpenSearch для OPDS-клиентов
- `GET /download/{id}` — скачать книгу
- `POST /scan` — загрузка файлов из `incoming`
- `GET /reader/{id}` — встроенный браузерный EPUB-ридер (Foliate-js)
- `GET /covers/{id}` — реальная обложка книги
- `POST /books/{id}/send-to-kindle` — отправка книги на Kindle по email (SMTP)
- `GET /highlights` — хаб цитат и заметок с экспортом в Markdown (`/highlights/export`)
- `GET /stats` — статистика, стрики и аналитика чтения
- `GET /plugins/yandex2kindle.koplugin.zip` — архив плагина для KOReader
- `GET /health` — состояние
- `GET /docs` — Swagger

Прогресс панели хранится отдельно для каждой книги. Последняя запись заменяет предыдущую, включая пустую позицию, если она не передана. Веб-форма процента сохраняет существующую позицию. Обмен с KOReader описан ниже; OPDS используется для скачивания файлов.

## Настройка интеграций

Создайте `.env` на основе [.env.example](../.env.example), заполните нужные параметры и пересоздайте контейнер:

```bash
docker compose up -d --build
```

Compose передаёт эти настройки в приложение. При запуске без Docker задайте их как переменные окружения: само приложение `.env` не читает. Файл `.env` исключён из Git. Используйте один процесс Uvicorn: планировщик и блокировка синхронизации работают внутри процесса.

### Яндекс Книги

Адаптер напрямую обращается к REST API Яндекс Книг по протоколу, проверенному по исходникам [неофициального yandex-book-api](https://github.com/stepan163s/yandex-book-api). Сторонний SDK не требуется: опубликованная версия 2.0.0 отличается от актуальной ветки GitHub. Для получения OAuth-токена из папки проекта выполните `python3 -m app.yandex_auth`. Нужен только Python 3, установка зависимостей и сборка Docker не требуются. Откройте напечатанную ссылку, войдите в Яндекс и вставьте полный адрес возврата в терминал (ввод скрыт). Сохраните выведенную строку `YANDEX_BOOK_TOKEN=...` в `.env`. В обновлённом образе также доступна команда `docker compose run --rm yandex2kindle python -m app.yandex_auth`.

Для автоматического обновления задайте `YANDEX_SYNC_INTERVAL_SECONDS=1800`: синхронизация запускается при старте приложения и затем каждые 30 минут после завершения предыдущей попытки. Минимальный интервал — 60 секунд; `0` отключает расписание. Ручной запуск доступен на странице «Внешние источники» и через `POST /api/integrations/yandex/sync`.

Синхронизируется личная библиотека из REST-маршрута `/profile/library_cards` с пагинацией `page/per_page` в записи списка чтения с источником `yandex:<логин>`. Сервис собирает все страницы перед записью: ошибка API отменяет весь импорт. Повторный запуск не добавляет дубликаты; изменения метаданных отслеживаются по UUID книги. Удаление книги из Яндекса не удаляет локальные записи. Удалённая вручную локальная запись может появиться при следующей синхронизации. Ошибки и время последнего запуска доступны на странице интеграций и в `GET /api/integrations`. Токен не включается в ответы и не передаётся каталогам.

### Поиск Flibusta и OPDS, импорт выбранной книги

**Z-Lib** доступен отдельным каталогом: поиск, выбор издания и импорт выполняются внутри приложения, включая версию Kindle. Приложение обращается к API `/eapi/book/search`, затем получает ссылку на файл через `/eapi/book/{id}/{hash}/file`. При ошибке сети, HTTP или неподдерживаемом ответе зеркала перебираются последовательно: `z-zibrary.bz`, `z-lib.mx`, `z-library.im`, `z-lib.sk`, `z-library.sk`, `z-lib.fm`, `libb.la`. Общий бюджет обращения к API с перебором зеркал — 90 секунд. Пустой успешный поиск не вызывает переход к другому зеркалу. Flibusta и Z-Lib используют независимые источники.

Под результатами поиска в веб-панели и Kindle есть блок «Зеркала каталога — открыть вручную»: ссылки на домены выбранного каталога остаются доступны во время поиска и при ошибке. Это дополнительная возможность; основной поиск и импорт работают внутри приложения.

Если Z-Lib требует авторизацию, задайте `ZLIB_REMIX_USERID` и `ZLIB_REMIX_USERKEY` из cookies вашей сессии в `.env` и пересоздайте контейнер. Эти значения отправляются только API перечисленных зеркал; в браузер и журнал они не передаются. Если ссылка на файл ведёт на отдельный CDN, добавьте его origin в `REMOTE_ALLOWED_ORIGINS`. Доступность зеркал, поддержка ими API, действительность сессии и лимиты скачивания зависят от Z-Lib. Из текущего окружения живые ответы этих доменов проверить не удалось.

Задайте `FLIBUSTA_SEARCH_URL` и/или `OPDS_SEARCH_URL` полным URL поиска с шаблоном `{searchTerms}`. Для нумерации страниц поддерживаются `{startPage}` и `{startPage?}`. Например, шаблон из [описания OpenSearch Flibusta](https://github.com/ryzed/flibusta-calibre-opds-store/blob/main/opds-opensearch.xml):

```dotenv
FLIBUSTA_SEARCH_URL=https://flibusta.is/opds/search?searchTerm={searchTerms}&searchType=books&pageNumber={startPage?}
```

Если поиск на `https://flibusta.is` завершается сетевой ошибкой, тайм-аутом или ошибкой HTTP, приложение автоматически повторяет запрос на `https://flibusta.site`, сохраняя параметры поиска и страницу. Ссылки на книги резервного каталога и его конвертер `https://static.flibusta.site` разрешены автоматически при основном адресе `https://flibusta.is`.

Доступность конкретного домена зависит от вашей сети. Для другого каталога возьмите шаблон Atom-поиска из его OpenSearch-описания. Нумерация страниц передаётся источнику как есть, по умолчанию с нуля; для каталога, начинающего с единицы, укажите страницу `1` в форме.

Откройте «Внешние источники» или нажмите «Найти файл» рядом с записью списка чтения. Результаты сортируются по сходству названия и автора; оценка помогает выбрать издание и не служит автоматическим подтверждением. Нажатие «Скачать и импортировать» загружает конкретный выбранный вариант и передаёт его в Calibre. Поиск сам не скачивает книги. Повторный импорт одинакового файла определяется по SHA-256.

Обычная страница каталогов и версия для Kindle открываются без обращения к внешнему источнику. Результаты загружаются отдельным фоновым запросом с терминальным индикатором; старые браузеры используют XMLHttpRequest. Название необязательно: можно искать только по автору или оставить оба поля пустыми (результат зависит от поддержки пустого запроса источником). Без JavaScript поиск доступен обычной отправкой формы.

Поддерживаются Atom OPDS acquisition/open-access ссылки на EPUB, FB2, FB2 ZIP, PDF, MOBI, AZW3 и TXT. FB2 ZIP распаковывается локально: архив должен содержать ровно один FB2 до 100 МБ; пути из архива не используются. Выбирайте FB2 ZIP, если конвертер EPUB источника недоступен: KOReader открывает исходный FB2. Доступность самого файла зависит от сервера; HTTP 403 означает отказ источника, а не необходимость увеличить тайм-аут. Buy/borrow/subscribe/sample-ссылки исключаются. На странице показывается до 200 записей ответа; другие страницы запрашиваются через поле номера страницы. Поисковый ответ ограничен 2 МБ, файл — 100 МБ. Подключение к источнику ожидается до 60 секунд (`REMOTE_CONNECT_TIMEOUT_SECONDS`, от 5 до 120). Для скачивания ожидание данных — 120 секунд, общий бюджет по умолчанию — 600 секунд (`REMOTE_DOWNLOAD_TIMEOUT_SECONDS`, от 30 до 3600). Для поиска ожидание данных остаётся 20 секунд. Варианты доступны для импорта один час, затем требуется повторить поиск. Тайм-аут подключения не определяет причину: нужно отдельно проверить DNS и соединение из контейнера. Само увеличение лимита не устраняет сетевые блокировки.

По умолчанию скачивание и перенаправления разрешены только на origin настроенного каталога. Если каталог отдаёт книги с CDN, явно добавьте его origin в `REMOTE_ALLOWED_ORIGINS` (например, `https://cdn.example.org`, несколько через запятую). Ошибка блокировки показывает точный origin без пути и параметров ссылки. Сохраните существующие адреса, добавьте указанный origin через запятую и примените настройку командой `docker compose up -d --build --force-recreate`. Настройки каталогов и разрешённых origin доверенные: не добавляйте неизвестные адреса. Клиент каталогов учитывает настройки прокси и CA, присутствующие в окружении процесса (`REMOTE_TRUST_ENV=true`); для прямого соединения задайте `false`. Само приложение не копирует прокси с компьютера в контейнер и не настраивает VPN.

Если `urllib` открывает `/opds`, а поиск приложения не работает, сравните клиенты на одном поисковом URL: `docker compose exec yandex2kindle python -m app.diagnostics`. Команда выполняет четыре проверки параллельно: urllib, HTTPX с окружением, HTTPX напрямую и HTTPX с прежним User-Agent `Yandex2Kindle/1.0` (`httpx_legacy_ua`). Первые три используют текущие заголовки приложения: браузерный User-Agent, Accept для XML/OPDS и Accept-Language. User-Agent можно переопределить через `REMOTE_USER_AGENT`. Заголовки не воспроизводят браузерную сессию или TLS-профиль и не гарантируют отсутствие 403; cookies из браузера приложение не получает. В отчёте есть статусы, длительность, типы ошибок и идентификатор сборки; значения прокси и OAuth-токен не выводятся. Идентификатор запущенной сборки также виден в `GET /health` и стартовом логе.

Flibusta может перенаправлять скачивание EPUB на свой конвертер `https://static.flibusta.is`; этот origin включён в `.env.example`. Для существующей настройки добавьте его в `REMOTE_ALLOWED_ORIGINS` и пересоздайте контейнер. При смене домена каталога повторите поиск: ранее найденные варианты содержат ссылки старого домена. Kindle подключается к локальному `/opds` приложения и не обращается к Flibusta напрямую: внешний файл сначала импортируется через веб-панель. Этапы поиска, скачивания и импорта, HTTP-статусы, число байт и тайм-ауты видны в `docker compose logs -f yandex2kindle`. OAuth-токен в эти сообщения не включается. Тайм-аут конвертера не означает ошибку Calibre: импорт в Calibre начинается после полной загрузки файла.

API:

- `GET /api/sources/flibusta/search?q=Название&author=Автор&page=0`
- `GET /api/sources/opds/search?q=Название&page=0`
- `POST /api/sources/import` с JSON `{"candidate_id":"идентификатор из поиска"}`
- `GET /api/integrations` — состояние настроек и последней синхронизации, без токенов

### Синхронизация KOReader

Сервис реализует [основной протокол KOReader Sync](https://github.com/koreader/koreader/blob/master/plugins/kosync.koplugin/api.json) на том же порту 8000:

1. В KOReader откройте настройки синхронизации прогресса и укажите собственный сервер `http://IP_КОМПЬЮТЕРА:8000` (без `/opds`).
2. Войдите с логином синхронизации со страницы «Аккаунт». Для обычного пользователя это его логин и пароль от сайта. Для владельца логин — `reader` (или `KOSYNC_LIBRARY_USER`): существующий пароль reader сохраняется; если такого аккаунта ещё не было, используется пароль владельца при создании. Аккаунт синхронизации создаётся автоматически вместе с личной библиотекой; регистрация из KOReader больше не нужна.
3. На остальных устройствах укажите тот же сервер и войдите в этот аккаунт.
4. Включите автоматическую синхронизацию в KOReader. Включение этой настройки выполняется на каждом устройстве.

Маршруты: `GET /users/auth`, `PUT /syncs/progress`, `GET /syncs/progress/{document}`, `GET /healthcheck`. Клиент использует заголовки `x-auth-user` и `x-auth-key`; второй содержит MD5 пароля, вычисленный KOReader. Сервис хранит только солёный PBKDF2-хеш этого ключа. `POST /users/create` требует сессии сайта и разрешает только свой логин; публичная регистрация закрыта независимо от `KOSYNC_ALLOW_REGISTRATION`. Изменение пароля и удаление аккаунтов через протокол пока не реализованы.

Состояние каждого пользователя изолировано. Прогресс пользователя `KOSYNC_LIBRARY_USER` также отображается в общей панели библиотеки. Книга сопоставляется по [частичному MD5 KOReader](https://github.com/koreader/koreader/blob/master/frontend/util.lua) или MD5 имени скачанного файла. Рекомендуется режим сопоставления **Binary** и одинаковые исходные файлы на устройствах. Старые книги индексируются автоматически при первой синхронизации; идентификаторы доступны в `GET /api/books/{id}/documents`. При неоднозначной контрольной сумме прогресс остаётся в аккаунте KOReader, но не привязывается к книге в панели.

Реальная позиция, пришедшая от KOReader, сохраняется в поле `position`. Изменение прогресса в панели или API передаётся обратно для этой позиции. Один лишь процент без позиции не отправляется на устройство: из него нельзя вычислить точную страницу EPUB. Для обмена между устройствами используется последняя запись, в том числе переход назад. Пользователи, отличные от `KOSYNC_LIBRARY_USER`, синхронизируются между своими устройствами без изменения общей панели.

### Цитаты Kindle и KOReader

Веб-ридер позволяет выделять текст, сохраняет CFI именно выбранного диапазона и восстанавливает подсветку при повторном открытии. Кнопки перелистывания находятся по краям, текст не перекрыт невидимой зоной нажатия. Ошибки сохранения показываются в ридере.

**KOReader:** скачайте `/plugins/yandex2kindle.koplugin.zip`, замените папку `yandex2kindle.koplugin` в каталоге `koreader/plugins` на устройстве и перезапустите KOReader. В меню плагина задайте URL сервера, логин и пароль синхронизации со страницы «Аккаунт». Для владельца логин обычно `reader`; у прежней учётной записи синхронизации пароль может отличаться от пароля сайта. Откройте книгу, скачанную из личного OPDS, и выберите «Синхронизировать цитаты этой книги». При включённой автоматической синхронизации плагин отправляет цитаты после изменения выделений, открытия книги и подключения сети. Без сети данные остаются в KOReader; повторите синхронизацию после подключения.

Цитаты и заметки KOReader появляются в хабе сайта без повторных копий. Правки заметок на устройстве обновляют импортированную запись. Удаление импортированной цитаты на сайте оставляет отметку, предотвращающую повторный импорт. Отсутствие цитаты в очередной отправке устройства не удаляет её с сайта автоматически. На устройстве пункт «Цитаты книги с сайта» показывает полученный общий список (до 2000 записей). Это отдельный список: плагин не превращает веб-цитаты в выделения внутри текста KOReader и не конвертирует CFI в XPointer. Если KOReader передаёт собственный EPUB CFI, сайт может отрисовать его; старые версии без CFI передают только текст/заметку. Совместимость позиции зависит от одинакового файла/издания. Протокол использует существующие заголовки `x-auth-user`/`x-auth-key` и изолированную библиотеку; новые сетевые порты не требуются.

**Штатная читалка Kindle:** автоматического доступа к облачным цитатам Amazon нет. Подключите устройство по USB и импортируйте `documents/My Clippings.txt` в разделе «Цитаты → Цитаты с Kindle и KOReader». Поддержаны выделения на русском/английском, файл UTF-8 до 8 МБ. Книги сопоставляются по названию и автору; неоднозначные/неизвестные записи пропускаются и учитываются в результате. Повторный импорт не создаёт копии. Дата в хабе для импортированных цитат — дата импорта.

Собранный Docker-образ включает папку плагина. Серверный обмен и импорт покрыты тестами; автоматические события плагина требуют отдельной проверки на физическом устройстве с вашей версией KOReader. Привязка к файлу проверяется по частичному MD5 KOReader, включая EPUB, полученный локальной конвертацией.

### Подробная статистика KOReader и WebDAV

На `/stats` можно импортировать `koreader/settings/statistics.sqlite3` вручную или
передавать её с Kindle через встроенный Cloud storage+. Поддерживается текущая
схема KOReader с таблицами `book` и `page_stat_data`, размер базы — до 64 МБ.
Перед ручным копированием закройте книгу и завершите KOReader, чтобы все записи
были сохранены в базе, включая данные из WAL.

Для подключения без USB:

1. KOReader → Инструменты → Cloud storage+ → добавить WebDAV.
2. Адрес: `http://IP_КОМПЬЮТЕРА:8000/webdav/`, начальная папка: `/`.
3. Укажите **логин и пароль сайта**. Для владельца это его логин сайта, а не
   отдельный логин синхронизации `reader`.
4. Статистика чтения → Настройки → Cloud sync → выберите этот сервер и корневую
   папку, затем «Синхронизировать сейчас». Обновите `/stats`.

На странице отображаются измеренное KOReader время по книгам, активность за
42 дня, серии дней чтения и сессии (записи одной книги с перерывами не более
30 минут объединяются). Календарь использует `READING_TIMEZONE`, по умолчанию
`Europe/Moscow`; часовой пояс применяется и к старой истории. Время через полночь
делится между датами. Оценка времени веб-читалки подписана отдельно: прогресс
KOReader сам по себе не содержит длительность чтения.

Импорт сохраняет также книги, которых нет в библиотеке. Связь с библиотекой
определяется по двоичному хешу KOReader, затем по однозначному совпадению названия
и автора. Позиция чтения при импорте статистики не меняется. Повторный импорт
объединяет записи по идентификатору книги, странице и времени начала; для уже
известной записи сохраняется большая длительность. Это соответствует принципу
объединения записей KOReader. Удаление истории на устройстве не удаляет ранее
импортированную аналитику платформы.

WebDAV предназначен только для `statistics.sqlite3` в корне, не для хранения
других файлов. Каждый пользователь получает собственные снимок базы и историю.
Поддерживаются `OPTIONS`, `PROPFIND` (Depth 0/1), `GET`, `HEAD`, `PUT`, `DELETE`,
ETag и условная запись `If-Match`/`If-None-Match`. Это позволяет KOReader повторить
объединение при одновременной отправке с устройств. Снимок и импорт сохраняются
одной транзакцией; некорректная база не заменяет предыдущую. `DELETE` удаляет
только WebDAV-снимок, не накопленную аналитику. Специальной настройки расписания
на сервере нет: отправку инициирует KOReader.

API ручного импорта: `POST /api/stats/koreader/import` (multipart, поле `file`).
`GET /api/stats` дополнительно возвращает `daily_activity`, `book_statistics`,
`koreader_reading_seconds`, `estimated_reading_seconds`, `koreader_import`,
`recent_koreader_sessions`, `koreader_books` и `timezone`.

## Связь Яндекс Книг, библиотеки и Kindle

Для отдельной проверки реального скачивания EPUB выполните `docker compose exec yandex2kindle python -m app.diagnostics --download https://flibusta.is/b/169962/epub`. Проверка использует загрузчик приложения, скачивает полный файл во временную папку, проверяет ZIP-mimetype EPUB и удаляет временный файл. В отчёт попадают этап, host/path без query-параметров, HTTP-статусы, версия протокола и факт наличия cookies без их значений. Для сравнения можно добавить `--http1` или `--no-session`.

По умолчанию загрузчик поддерживает HTTP/2 (`httpx[http2]`, `REMOTE_HTTP2=true`). Для Flibusta перед скачиванием запрашивается страница книги в той же HTTP-сессии (`REMOTE_BOOK_SESSION=true`), cookies сохраняются клиентом, а Referer передаётся с удалением query/fragment и сокращением до origin при переходе на CDN. Браузерные cookies автоматически не извлекаются. Временные HTTP 502/503/504 при скачивании повторяются один раз до записи данных; 403 и прерванная передача файла не повторяются автоматически.

В «Списке чтения» видны локальные статусы: «Хочу прочитать», «В библиотеке», «На Kindle · отмечено вручную», «Открыто в KOReader», «Читаю» и «Прочитано». Фильтры показывают ещё не найденные книги, все записи с файлом, отметки Kindle и состояние чтения. Статус Яндекса (например, `pending`/`reading`/`finished`) показывается отдельно и не заменяет локальный прогресс.

При старте, синхронизации Яндекса, импорте файла и добавлении записи списка приложение ищет однозначное совпадение названия и автора. Нормализация учитывает регистр, пунктуацию, ё/е и порядок слов имени; при совпадении имени и фамилии допускается дополнительное отчество. Без автора или при нескольких подходящих локальных файлах связь автоматически не создаётся. Кнопка «Сопоставить с библиотекой» запускает повторную проверку существующих записей.

Через «Связать с книгой в библиотеке» можно выбрать файл вручную (в списке выбора — последние 500 книг). Если нажать «Найти книгу» у записи списка чтения и импортировать выбранный результат, эта конкретная запись связывается с полученным файлом, даже если названия изданий различаются или файл уже импортирован ранее. Ручные связи переживают повторную синхронизацию Яндекса. «Убрать неверную связь» отключает автоматическое сопоставление для этой записи до нового ручного выбора; сам файл и его прогресс не удаляются.

На странице книги в «Учёте и доставке Kindle» можно отправить EPUB по SMTP, если настроены `SMTP_HOST` и `SMTP_FROM`, а адрес получателя указан в аккаунте или `KINDLE_EMAIL`. Успешная отправка сохраняет отдельную отметку «Отправлено по email» и не подтверждает наличие книги на устройстве. Отметку «Уже на Kindle» пользователь устанавливает вручную. Приложение не имеет доступа к библиотеке Amazon. Старые отметки «На Kindle» сохраняются: по прежним данным невозможно отличить ручное подтверждение от старой SMTP-отправки. Скачивание файла через браузер/OPDS не выставляет отметку Kindle. Полученный прогресс от KOReader подтверждает только открытие в KOReader; этот факт хранится отдельно от ручной отметки Kindle. Прогресс больше нуля/100% отображается как «Читаю»/«Прочитано». Учёт связан с локальным файлом; если несколько записей Яндекса вручную привязаны к одному файлу, они показывают общий прогресс и отметку устройства. Изменения не записываются обратно в аккаунт Яндекса.

API: `GET /api/wishlist` возвращает дополнительные поля `book_id`, `link_method`, `status`, `status_label`, `kindle_confirmed_at`, `reader_seen_at`, `yandex_states`; `POST /api/library/reconcile` запускает сопоставление; `PUT /api/wishlist/{id}/book` с `{"book_id":123}` задаёт связь, `DELETE` по тому же пути отменяет её; `PUT /api/books/{id}/kindle` с `{"on_device":true}` ставит ручную отметку (`false` снимает). `POST /api/sources/import` принимает необязательный `wish_id` для явной привязки результата.

## Локальная выгрузка EPUB

Кнопка «EPUB» у книги вызывает `GET /download/{id}/epub`. Уже имеющийся EPUB скачивается напрямую. Для FB2 и других поддерживаемых Calibre исходников приложение запускает `ebook-convert` локально, без конвертера Flibusta. Результат сохраняется в `data/converted` и используется повторно. Исходный файл, привязки списка чтения и прогресс не меняются. Лимит конвертации — 180 секунд, выходной файл — до 500 МБ. В Docker инструмент входит в установленный Calibre; при локальном запуске нужен `ebook-convert` в PATH. При изменении формата позиции KOReader могут различаться, поэтому ранее сохранённая позиция относится к исходному файлу.

## Проверка

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m unittest discover -s tests -v
```

Тесты используют временную SQLite-базу, имитацию Calibre, HTTP-транспорт каталогов и клиент Яндекса. Проверяют поиск, OPDS, список чтения, прогресс, импорт и дубликаты, пагинацию и ошибки Яндекса, расписание, перенаправления, лимиты, аутентификацию KOReader и обмен с панелью. Для проверки на реальных сервисах нужны OAuth-токен, доступный каталог, Calibre и устройство с KOReader.

## Безопасность и ограничения

Веб-панель, API, документация, OPDS и скачивание требуют авторизации. Без входа открыты только форма входа, статические ресурсы и health-проверки. Для доступа через интернет обязателен HTTPS через настроенный reverse proxy; порт 8000 не должен быть напрямую доступен из интернета. HTTP Basic и протокол KOReader не шифруют учётные данные сами по себе. Текущая конфигурация Compose предназначена для локальной сети; полноценный публичный хостинг здесь не настраивается. Авторизация не даёт прав на распространение книг. Файлы из защищённых подписок не извлекаются. Используйте только книги, которые вы вправе скачивать и передавать. Экспорт метаданных из Calibre пока не реализован. Метаданные книги в Calibre могут отличаться от введённых в веб-панели: Calibre при импорте читает метаданные из файла.

Синхронизация Яндекса переносит метаданные в одном направлении; она не переносит файлы подписки или позиции чтения Яндекса. Подбор внешних изданий выполняется по названию и автору с ручным выбором; автоматическое сопоставление по ISBN пока отсутствует.
