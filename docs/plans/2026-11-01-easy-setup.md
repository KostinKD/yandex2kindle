# Простая установка и настройка из браузера

Пользователь поручил сделать самостоятельное развёртывание понятным новичку: запуск файлом, создание аккаунта и ввод ключей на сайте, помощь при незавершённой настройке.

## Подход

Сохраняем Docker и текущий backend. Нативная упаковка Calibre для нескольких ОС — отдельная задача; текущая поставка включает запускаторы macOS/Windows/Linux и понятный переход к официальной установке Docker, если он отсутствует. После установки Docker повторный запуск выполняется одним файлом и открывает браузер. Установку системных компонентов и возможную перезагрузку нельзя честно назвать полностью автоматическими.

Первый владелец создаётся через `/setup` с одноразовым локальным ключом: запускатор передаёт его в URL fragment, не в query. Ключ хранится в файле с правами 0600, не выводится в логи и становится недействительным после создания владельца. Повторный захват установленной библиотеки запрещён.

Страница `/settings` доступна владельцу: Яндекс, SMTP, каталоги, Telegram, адрес устройства. Никакого ручного редактирования .env для обычного сценария. Значения из БД имеют приоритет над .env; пустое секретное поле сохраняет существующий ключ, отдельное действие отключает. Секреты не возвращаются в HTML/API. Локальное хранилище конфигурации защищено правами доступа, без заявления о шифровании.

Проверки подключений не посылают письма/Telegram-сообщения и не импортируют книги. «Сохранено» отличается от «Проверено». Яндекс OAuth использует существующий проверяемый state/callback: сайт проводит по шагам, пароль Яндекса приложению не нужен.

Неподключённые опции не мешают чтению; стартовый checklist и ссылки на нужный раздел помогают завершить настройку. Конфигурация применяется без пересборки; Telegram подхватывает её в следующем цикле опроса.

## План проверки

- [x] Тесты начального владельца: неправильный ключ, Origin, повторная регистрация, действующая сессия после установки.
- [x] Owner-only настройки, маскировка секретов, сохранение/очистка, .env fallback, немедленное использование интеграциями.
- [x] Проверки подключений и OAuth: HTTP failures, недействительный state, отсутствие ключей в ответах.
- [x] Динамические фоновые задачи с сохранением прежних .env-настроек.
- [x] Запускаторы и безопасный архив без данных/ключей, инструкция для новичка.
- [x] Полный unittest, браузер: чистая установка и существующая библиотека; Docker-проверка.

## Результаты

164 теста прошли локально и в Python 3.11 внутри Docker с read-only монтированием исходников и временными данными. Проверены bootstrap capability, повторная регистрация, сессия, owner-only настройки, .env fallback, хранение пустых/очищенных ключей, OAuth state, ошибки SMTP без утечки секретов, отсутствие отправки письма при проверке, пробуждение отключённого планировщика после изменения настроек. Подпроцессный тест запускатора проверил занятый порт, открытие URL с fragment и сохранность существующего .env; тест архива проверил отсутствие личных данных и права запуска.

Chromium: чистый первый запуск, ввод ключа в fragment и удаление его из адресной строки, регистрация владельца, автоматическая сессия, сохранение секрета и повторное пустое поле, отсутствие секрета в HTML/API, SMTP preset, ширины 1365/390 без переполнения и pageerror. Реальные подключения к почте/Яндексу в проверках не выполнялись.

Рецензент выявил несовместимые с Python 3.11 кавычки в трёх f-строках Telegram; исправлено и подтверждено полным прогоном тестов в Docker. Сценарий PowerShell просмотрен и упакован с UTF-8 BOM для Windows PowerShell; запуск на физическом Windows не выполнялся.

Архив для передачи: `dist/Yandex2Kindle.zip`. Инструкция доступна как HTML и Markdown в корне. Основные ограничения: Docker устанавливается отдельно, могут понадобиться системное подтверждение/WSL/перезагрузка; это не подписанный нативный установщик. Ключи хранятся локально с файловыми правами, не заявляется шифрование.
